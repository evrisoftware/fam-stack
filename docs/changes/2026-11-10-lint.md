## What failed

Several of the template's rules were held by review alone: selector prefixes, signal inputs
and outputs, `inject()`, `@if`/`@for`, no `style=""`, alt text and keyboard-reachable click
handlers, no `@angular/fire` or `rxfire`, and Firebase opened only by `provideFirebase`. A change that broke one compiled, passed the
specs and reached the repository unless a reviewer caught it.

## What changed

`npm run lint` runs ESLint over `projects/` with `eslint.config.mjs`, and `npm run verify`
runs it after the entry check, so CI does too. New devDependencies: `eslint`,
`angular-eslint` and `typescript-eslint`.

The config takes typescript-eslint's and angular-eslint's recommended sets, the template
accessibility set, and on top of them:

- component and directive selectors prefixed `fam` in the layer and `app` in the app;
- `prefer-signals`, `prefer-output-emitter-ref`, `prefer-host-metadata-property`;
- `prefer-control-flow`, `button-has-type`, and `no-inline-styles`, which refuses a literal
  `style=""` and `ngStyle` and lets any `[style.x]` binding pass (a hard-coded colour in one
  is still for review to catch);
- `no-restricted-imports` for `@angular/fire` and `rxfire`, for Angular's `ɵ` exports, and
  for `initializeApp`, `initializeAuth`, `initializeFirestore`, `getAuth` and `getFirestore`
  outside `provide-firebase.ts` (type-only imports pass).

Inline templates are linted like `.html` files. Lint does not check the name of an icon-only
button, quotes or indentation. The original needed no code change to pass; its five
deliberate exceptions are overrides in the config, each naming its file.

## Adopt

1. `npm install --save-dev eslint angular-eslint typescript-eslint`, with `angular-eslint`
   in your Angular major.
2. Copy `eslint.config.mjs`. Change the `app` prefix if your app's selectors use another.
3. Add the script `"lint": "eslint projects"` and put `npm run lint` in `verify` after
   `check:entries`.
4. Run `npm run lint`. Fix what it reports in your own code. Where a report is a pattern you
   chose on purpose, add an override for that file in the config with a one-line comment;
   do not scatter disable comments. Drop the overrides for files you no longer have.

## Check

`npm run lint` exits clean. A component with `selector: 'x-probe'`, an `@Input()` and a
`*ngIf` in its template gets one report for each; delete it afterwards.
